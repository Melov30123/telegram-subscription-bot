# Telegram Subscription Bot 4.0

Production-ready Telegram-бот для продажи доступа в закрытый канал через Telegram Stars.
Проект рассчитан на базу порядка 10 000+ пользователей, хранит операции в PostgreSQL и
управляется прямо из Telegram через интерактивную админку.

## Что умеет бот

- несколько включаемых и отключаемых тарифов;
- безопасная оплата Telegram Stars с одноразовыми счетами, pre-checkout-проверкой и
  идемпотентной обработкой;
- отдельная продажа цифрового гайда с секретной ссылкой Google Drive, повторной выдачей
  только покупателям и независимой ценой;
- автоматическое продление действующей подписки и персональные одноразовые ссылки;
- автоматическое удаление из канала после окончания доступа;
- напоминания за 7, 3 и 1 день без повторных отправок;
- интерфейс пользователя на русском, английском и испанском;
- промокоды с длительностью и лимитом активаций;
- возврат Stars администратором с корректировкой срока доступа;
- сегментированные фоновые рассылки (`all`, `active`, `expired`) с текстом и медиа;
- поиск и карточки пользователей, блокировки покупок, ручная выдача и отзыв доступа;
- CSV-экспорт, история платежей и неизменяемый журнал действий администраторов;
- `/healthz`, `/readyz` и JSON-метрики;
- автоматические SQL-миграции, Docker, CI и ежедневные резервные копии.

## Архитектура

```text
Telegram-bot/
├── app.py                         # совместимая точка запуска
├── subscription_bot/
│   ├── routers/                   # пользователь, платежи, админка
│   ├── migrations/                # версионируемая схема PostgreSQL
│   ├── database.py                # транзакции и запросы
│   ├── services.py                # доступ и фоновые рассылки
│   ├── jobs.py                    # удаление истёкших и напоминания
│   ├── health.py                  # health/readiness/metrics
│   └── main.py                    # сборка приложения
├── tests/
├── Dockerfile
└── docker-compose.yml
```

PostgreSQL хранит профили, тарифы, одноразовые платёжные intent-ы, платежи, периоды
подписок, ссылки, промокоды, рассылки, напоминания и audit log. Критический путь оплаты
выполняется одной транзакцией, поэтому повторное Telegram-событие не выдаст подписку
дважды.

## Быстрый запуск через Docker

1. Создайте бота в [@BotFather](https://t.me/BotFather) и добавьте его администратором
   закрытого канала. Нужны права приглашать и блокировать пользователей.
2. Узнайте числовой ID канала (обычно начинается с `-100`) и Telegram ID каждого
   администратора.
3. Скопируйте конфигурацию:

   ```bash
   cp .env.example .env
   ```

4. Обязательно измените `BOT_TOKEN`, `CHANNEL_ID`, `ADMIN_IDS`, `POSTGRES_PASSWORD`,
   `SUPPORT_USERNAME` и `TERMS_URL`.
5. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```

Проверка состояния:

```bash
curl http://127.0.0.1:8080/readyz
```

Миграции применяются автоматически перед стартом polling. Первый тариф создаётся из
`DEFAULT_PLAN_*`, только если таблица тарифов пуста. Дальше тарифы управляются в админке.

## Запуск без Docker

Требуются Python 3.11+ и PostgreSQL 15+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

В Windows активация окружения: `.venv\Scripts\activate`.

## Настройки

| Переменная | Обязательна | Назначение |
|---|---:|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `DATABASE_URL` | да | PostgreSQL DSN |
| `CHANNEL_ID` | да | ID или `@username` закрытого канала |
| `ADMIN_IDS` | да | Telegram ID через запятую |
| `DEFAULT_PLAN_*` | нет | первый тариф для пустой БД |
| `GUIDE_DOWNLOAD_URL` | нет | секретная ссылка на гайд; без неё товар отключён |
| `GUIDE_PRICE_STARS` | нет | отдельная цена гайда в Stars, по умолчанию `500` |
| `GUIDE_TITLE` | нет | название гайда в счёте Telegram |
| `SUPPORT_USERNAME` | нет | контакт для `/paysupport` |
| `TERMS_URL` | нет | публичные условия и возвраты |
| `TIMEZONE` | нет | часовой пояс фоновых задач |
| `DROP_PENDING_UPDATES` | нет | обычно оставьте `false`, чтобы не терять оплаты |
| `BROADCAST_RATE_PER_SECOND` | нет | безопасно `20`, максимум проекта `25` |
| `PORT` | нет | HTTP health server, по умолчанию `8080` |

Не публикуйте `.env`. Токен бота и пароль БД никогда не отправляйте в чат и не добавляйте
в Git.

### Настройка гайда на Render

Откройте сервис бота → **Environment** и добавьте три переменные:

```text
GUIDE_DOWNLOAD_URL=https://drive.google.com/file/d/FILE_ID/view?usp=drive_link
GUIDE_PRICE_STARS=500
GUIDE_TITLE=Практический гайд
```

Замените `500` на нужную цену. Ссылку Google Drive настройте на просмотр «всем, у кого
есть ссылка», иначе оплативший пользователь не сможет открыть файл. После сохранения
переменных выполните **Deploy latest commit**. Ссылка не хранится в GitHub и показывается
только после успешной оплаты. Команда `/guide` повторно выдаёт её покупателю; возврат
Stars отзывает право на повторную выдачу.

## Админка

Команда `/admin` открывает кнопочную панель. `/admin_help` показывает все доступные
команды с примерами. Основные операции:

```text
/stats
/users [ID или username]
/user ID
/grant ID ДНИ [ПРИЧИНА]
/revoke ID [ПРИЧИНА]
/kick ID
/block ID
/unblock ID
/notify ID ТЕКСТ
/payments [КОЛИЧЕСТВО]
/refund TELEGRAM_CHARGE_ID
/guide
/plans_admin
/plan_add CODE STARS ДНИ НАЗВАНИЕ
/plan_toggle CODE
/promos
/promo_add CODE ДНИ ЛИМИТ
/promo_disable CODE
/broadcast [all|active|expired]
/export
/audit [КОЛИЧЕСТВО]
/health
```

Администраторы задаются только в `ADMIN_IDS`; так злоумышленник не сможет выдать себе
права через базу или Telegram-команду. Каждое существенное действие пишется в audit log.

## Резервное копирование

Ручной бэкап:

```bash
docker compose exec -T postgres pg_dump -U subscription_bot -d subscription_bot \
  --format=custom > subscription_bot.dump
```

Восстановление в пустую БД:

```bash
docker compose exec -T postgres pg_restore -U subscription_bot -d subscription_bot \
  --clean --if-exists < subscription_bot.dump
```

Готовый скрипт `deploy/backup.sh` хранит последние 14 дней. Настройте cron и копирование
архивов на отдельный сервер или S3-совместимое хранилище. Бэкап на том же VPS не защищает
от потери всего сервера.

## Рекомендуемый сервер

На 2 августа 2026 года практичный вариант для оплаты из РФ — **Timeweb Cloud,
Cloud MSK 50**: 2 vCPU, 4 ГБ RAM, 50 ГБ NVMe, 1 Гбит/с; на странице провайдера при оплате
за 12 месяцев указано 1 062 ₽/месяц. Этого достаточно для бота и PostgreSQL при 10 000
подписчиков с большим запасом, поскольку определяет нагрузку число одновременных событий,
а не размер таблицы пользователей.

- Тарифы: https://timeweb.cloud/services/cloud-servers/
- Подробная установка: [DEPLOY.md](DEPLOY.md)

Более простой PaaS-вариант — Railway Hobby: минимум $5/месяц, затем оплата реального CPU,
RAM и диска. Он удобнее в один клик, но итоговая цена приложения плюс постоянно работающей
PostgreSQL обычно менее предсказуема, чем один VPS.

## Проверка перед релизом

```bash
pip install -r requirements-dev.txt
ruff check .
pytest -q
docker compose config
```

До приёма реальных платежей проведите покупку минимального тестового тарифа, проверьте
`/invite`, повторное продление, `/refund`, удаление из канала и восстановление тестового
бэкапа.
